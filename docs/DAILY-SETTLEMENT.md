# 按站按日充电结算（日结）数据字典

面向充电站财务：每日 9:00 前出前一日充电结算。辅助用电表常在下午才回传，系统把未回传部分
**显式挂“待补辅助用电”，绝不作零、绝不计入客户损耗**，先出账也不冤枉客户；下午补数后重跑，
自动生成新版本并保留字段级变化轨迹。

## 输入 CSV 契约

文件名不限，编码支持 UTF-8（含 BOM）与 GB18030，严格 CSV，首行表头。必填列：

| 列 | 含义 | 取值 |
|---|---|---|
| `id` | 读数号 | 非空字符串 |
| `station` | 站点 | 非空字符串 |
| `biz_date` | 业务日期 | `YYYY-MM-DD`，按 +08:00 自然日 |
| `kind` | 读数类型 | `meter` 总表 / `order` 订单 / `aux` 站方辅助表 |
| `energy` | 电量 | kWh 或 MWh；辅助表允许 `未知/空/-/N/A/NULL` 哨兵 |
| `unit` | 单位 | `kWh` 或 `MWh`（MWh ×1000 归一为 kWh） |
| `order_no` | 订单号（可选） | 仅订单使用 |
| `start`/`end`（可选） | 时间窗口 | 若提供必须正好覆盖该业务日 00:00–次日 00:00（+08:00） |

未知哨兵不等于零：仅 `aux` 允许未知（表示未回传占位）；`meter`/`order` 未知直接隔离。
全角数字按 NFKC 归一解析。字段数不符、坏类型、坏日期、负电量等均带原始行号隔离。

## 四方对账恒等式

每个站日：

```
总表电量 = 订单电量 + 客户损耗 + 站方辅助用电 + 待补辅助用电
```

- `订单电量`：该站日全部订单 kWh 之和。
- `站方辅助用电`：辅助表已回传时的读数；**未回传为 `None`（展示“未回传”），不是 0**。
- `客户损耗`：仅在辅助表已回传时确认，= 总表 − 订单 − 辅助；待补态不确认（展示“未确认”）。
- `待补辅助用电`：辅助表未回传时，把“总表 − 订单”的全部差额挂此科目，单独交代；回传后清零并
  把对应金额确认为客户损耗或辅助用电。
- 所有可结算站日落库前必须通过恒等式校验，否则整批退回、旧版保留。

### 站日状态

| 状态 | 触发条件 | 能否出账 |
|---|---|---|
| `可结算-完整` | 总表唯一、有订单、辅助已回传、差额非负且恒等式平衡 | 是 |
| `可结算-待补辅助` | 总表与订单齐全，仅辅助表未回传 | 是，差额挂待补，客户损耗未确认 |
| `异常-不可结算` | 总表缺失/重复、辅助表重复、无订单、或差额为负 | 否，列原因码，不参与结算 |

## 输出字段（每站日一行）

| 字段 | 含义 |
|---|---|
| `meter_kwh` / `order_kwh` / `aux_kwh` | 总表 / 订单 / 辅助电量，未知为 `null` 而非 0 |
| `customer_loss_kwh` | 客户损耗；待补态为 `null`（未确认，不作零） |
| `pending_aux_kwh` | 待补辅助用电；完整日为 `0.000`，待补日承载全部差额 |
| `gap_kwh` | 总表 − 订单 −（已知辅助）的差额 |
| `status` | 站日状态（见上） |
| `codes` | 原因码清单（如 `D_MISS_AUX`、`D_MISS_METER`、`D_NEG_LOSS`） |
| `source_lines` | 来源 CSV 行号，供溯源 |
| `reconcile.identity_pass` | 四方恒等式是否平衡 |

## 版本化、复核与追溯

- 自然键为（站点，业务日期）；内容哈希相同则同日重跑**复用同一版本，不新增**。
- 内容变化（如下午补数）写入新版本，`changes` 记录每个字段 `旧值 → 新值`，旧版本永久保留。
- 复核（通过/退回）使用整数版本乐观锁，陈旧提交返回 `409 STALE`；复核后版本号自增。
- **已复核（非“待复核”）日结锁定**：后续导入不覆盖，仅在批次结果 `blocked` 中交代；需人工
  “解锁”后才能重新覆盖，解锁动作留痕。
- 整批先在内存算完并校验恒等式，再在单事务内落库；任何异常整体回滚，当前版本与旧版均不动。

## 接口与页面

| 入口 | 方法 | 说明 |
|---|---|---|
| `/daily` | GET | 日结台账页面（筛选、导入、批次、跳转明细） |
| `/daily/detail?station=&biz_date=` | GET | 四方对账、复核/解锁、版本轨迹 |
| `/api/daily/runs` | POST | 计算并保存（JSON `{text}` 或 multipart 文件） |
| `/api/daily/preview` | POST | 仅预览，不落库 |
| `/api/daily/settlements` | GET | 当前版本台账，支持 `station/biz_date/status` 过滤 |
| `/api/daily/settlements/<id>` | GET | 单个版本详情 |
| `/api/daily/versions?station=&biz_date=` | GET | 该站日全部历史版本 |
| `/api/daily/review` | POST | 复核 `{station,biz_date,decision,version,note}` |
| `/api/daily/reopen` | POST | 人工解锁 |
| `/api/daily/batches`、`/api/daily/batches/<run_id>` | GET | 批次清单/详情 |
| `/api/daily/export.csv` | GET | 台账导出，未知输出“未回传/未确认”而非 0 |

数据保存在 `DATA_DIR/daily.sqlite`，与分时账的 `runs.sqlite` 物理分离、互不影响。

## 边界

只处理电量口径下的总表、订单、客户损耗与站方辅助用电对账，**不含停车服务费、不含需量电费**。
计量段内匀速等分时电价口径仍由 M1–M7 子系统负责，本子系统只做按站按日的电量四方结算。
